**Agent 能自己算出调度参数**（不再是从四个固定配置里挑），两个混部场景的网页 p99 相对内核默认分别降 **52.8%** 和 **75.1%**，

一次多资源联动演示的 **13 项检查全部通过**。

## 二、可直接用的数字

### 实验一：CPU 调度（5 组 × 2 场景 × 单轮 7 窗口）

| 组 | 配置 | 吞吐混部 p99 (ms) | 延迟混部 p99 (ms) | 后台 EPS（吞吐/延迟） |
|---|---|---:|---:|---:|
| A | 内核默认 EEVDF | 5.563 | 14.687 | 5744 / 4397 |
| B | SCX 1 ms + 唤醒抢占 | 2.705 | 3.779 | 5270 / 3925 |
| D | SCX 20 ms + 唤醒抢占 | 2.837 | 3.821 | 5267 / 3900 |
| E | SCX 300 µs + 唤醒抢占 | **2.601** | 3.687 | 5246 / 3877 |
| C | **Agent 自己算** | **2.625** | **3.655** | 5256 / 3926 |

- Agent 实际选出的片长：吞吐混部 **300 µs**，延迟混部 **700 µs**（内核回读，不是它自报）。
- 10 次运行请求错误全部为 0，实际 RPS 与完成率 99.99%–100.02%。
- 相对默认：C 组 −52.8% / −75.1%；相对最佳固定配置（300 µs）：−0.9% / +0.9%（即打平，差异在测量噪声内）。

### 实验二：Cgroup CPU 份额（2 组 × 2 轮，默认调度）

| 组 | shares（普通:高优先） | 高优先组占比 | 普通组占比 | 实测比值 |
|---|---|---:|---:|---:|
| A | 1024 : 1024 | 50.00% | 50.00% | 1.000 : 1 |
| B | 1024 : 4096 | **80.06% / 80.00%** | **19.94% / 20.00%** | 4.014 : 1 / 4.000 : 1 |

两轮都复现，偏差 ≤0.06 个百分点；进程迁出与 cgroup 删除全部验证通过。

### 实验三：eBPF 端口隔离（2 组 × 2 轮）

| 组 | 正常期 p99 | **冲击期 p99** | 恢复期 p99 | 目标端口 成功/失败 | 丢包数 |
|---|---|---:|---:|---|---:|
| A 只观测 | 3.688 / 3.701 | **11.733 / 12.391** | 14.822 / 6.400 | 17 167 / 0；16 894 / 0 | 0 |
| B 自动隔离 | 3.828 / 51.411 ※ | **3.805 / 4.022** | 3.710 / 3.719 | 194 / 656；189 / 656 | 779 / 777 |

※ B 组第 2 轮"正常期"均值被首窗 99.14 ms 拉高，那一窗与 eBPF 钩子加载/挂载同时发生，属于启停开销；
该轮冲击期与恢复期不受影响。这条在报告 4.2 节有完整说明，汇报时不要删。

触发：冲击开始后 0.2–0.3 s（观测包速率 2 130–2 210 pps，阈值 20 pps）；解除：冲击停止后 0.6–0.7 s（观测 ~11.9 pps）。

### 联动演示

5 个阶段、13 项检查全部通过（感知 → 决策 → 执行 → 回读 → 回退），含默认调度下自动 4096:1024 实测 **3.91 : 1（79.7% / 20.3%）**。

## 四、必须保留的边界（汇报里不能省）

1. **只有一轮**（实验一）：单轮 7 窗口，没有样本 SD、没有顺序对换，只作描述性比较，**不声称统计显著**。
2. **20 ms 那组不可复现**：同配置两次实测，吞吐混部 p99 分别是 10.167 ms 和 2.837 ms（差 3.6 倍）。所以不能说"20 ms 稳定更差"，
   只能说"长片长的退化是偶发的，表现为不可预测"。
3. **Agent 与最佳固定配置打平**，不是超越。差异 0.9% 在噪声内。
4. **Cgroup 只在默认调度下成立**：当前 SCX 后端没有实现 cgroup 权重语义，不能说"SCX 下同样有效"。
5. **eBPF 隔离的是整个目标端口**：触发后该端口的合法连接也会被丢；包速率统计 ≠ HTTP 请求数。不能说"能识别并只拦恶意请求"。
6. **实验二的坏样本**：20 ms 组的"坏"主要来自**抢占开关**而不是片长——短探针显示抢占开着时片长 1→20 ms 对延迟几乎没影响，
   一旦关掉抢占，10 ms 就崩到 1 910 ms（完成率 0.89）。这条是加分项，讲清楚会显得懂原理。
7. **单机、两场景、一台虚拟机**。不要外推到生产。
