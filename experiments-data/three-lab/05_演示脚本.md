# 现场演示脚本（网页界面）

> 面向：答辩现场。目标是在 **6–8 分钟**内，用真实页面把"Agent 自主选参 + Cgroup + eBPF"三件事各演一遍。
> 页面地址：`http://192.168.200.130:8899/`（来宾服务直接监听 0.0.0.0:8899，已验证返回 200）。
> 若被防火墙挡住，用隧道：`ssh -L 8899:127.0.0.1:8899 root@192.168.200.130`，然后开 `http://127.0.0.1:8899/`。

---

## 0. 演示前的 60 秒检查

| 检查 | 怎么看 | 期望 |
|---|---|---|
| 服务在跑 | 页面能打开、右上角有实时数字在跳 | 正常 |
| 调度器干净 | 页面「SCX / BPF Map」证据面板，或来宾执行 `cat /sys/kernel/sched_ext/state` | `disabled` |
| 无残留钩子 | 页面 eBPF 区显示"未挂载"，或 `tc filter show dev lo egress` 为空 | 空 |
| 标签页保持前台 | 浏览器不要切到别的标签太久 | 超过 90 秒不轮询会**自动停负载并恢复默认** |

> 演示前把场景选到「延迟优先混部」，让它先跑起来预热 30 秒以上，曲线有历史可比。

---

## 1. 演示一：默认调度 vs Agent（约 3 分钟，核心）

**这一步要证明**：Agent 会自己算出一个片长，并把尾延迟压下来。

1. 场景下拉选 **「延迟优先混部」**，说明一句：
   > 25 600 RPS 的网页流量 + 1 个纯自旋线程，两者抢同一个核。
2. 先看**默认调度**的 p99 —— 稳定在 12–18 ms 左右。这是基线，先让观众看 10 秒。
3. 点 **「自动 Agent」** 按钮。说明它会做三件事：
   > 读前端的实测排队时长 → 算出起点片长 → 用加权分判断保不保留。它拿不到场景名，也没有 p99 达标线。
4. **等 15–25 秒**，盯着状态文字的变化顺序：
   `观测中（采集基线） → 确认中 → 试用中 → 已接受 / 保持`
   p99 会从 12–18 ms 掉到 **3.5–4 ms**。
5. **展示它选了什么参数**（这是本次演示的重点）：
   - 右侧「当前策略依据」那一行会变成：
     `Agent holding：本次搜索已用 2 个探测点，保持最优点 SCX 300μs + 唤醒抢占（加权分 …）`
   - 再点证据面板的 **「SCX / BPF Map」**，看**内核真实回读**的 `slice_ns`（例如 300000000 表示 300 µs）。
   - 口播：
     > 这不是四个预设之一，是它自己算出来的；内核回读和它上报的一致。

**如果观众问"多久收敛"**：老实说 12–23 秒，取决于它排第几个上去。

---

## 2. 演示二：切负载不刷新（约 1 分钟）

1. 下拉切到 **「吞吐优先混部」**（4 000 RPS + 4 个自旋线程）。
2. 指出：**页面没有刷新**，曲线保留前后两段，并自动打了场景分界线。
3. Agent 会重新观测（CPU 压力变化会重建基线），再等 10–20 秒稳定。
4. 口播：
   > 场景切换只改负载，不会告诉 Agent 场景名，也不会替它选策略。

---

## 3. 演示三：Cgroup 4:1（约 1 分钟）

1. 先点 **「实测 1:1 (1024:1024)」** → 两个同核计算任务各拿 50%。
2. 再点 **「实测 1:4 (1024:4096)」** → 高优先组 **80%**、普通组 **20%**。
3. 口播：
   > 高优先任务多拿的 60% 是从普通组手里重新分配的，不是凭空来的。
   > 这是**默认 CFS 调度**下的权重；当前 SCX 后端没有实现 cgroup 权重语义，所以不能说到 SCX 上。

---

## 4. 演示四：eBPF 端口隔离（约 2 分钟）

1. 点 **「🟢 观测模式（放行）」**。
   口播：钩子挂在 lo 上，只统计目标端口 18095 的包，全部放行。
2. 点 **「💥 注入端口突发洪泛（触发 Agent 自动熔断）」**。
   - 观察 Agent 把状态自动翻成 **🔴 阻断**，丢包计数从 0 开始涨。
   - 这一步是 Agent 自己判的（目标端口包速率超过阈值 20 pps），不是手动点的阻断按钮。
3. 点 **「📡 发送真实 HTTP 探测」**：
   - 此时探测**失败**（连接被 TC 丢弃）。
4. 等冷却（几秒），状态自动回到 **🟢 观测**，再点一次探测 → **成功**。
5. 口播边界（一定要说）：
   > 规则隔离的是**整个目标端口**，触发后该端口的合法连接一样被丢；包速率统计也不等于 HTTP 请求数。

---

## 5. 收尾（30 秒）

1. 点 **「停止测试并恢复默认」**。
2. 确认：`sched_ext` 回到 `disabled`、eBPF 区显示未挂载。
3. 口播：
   > 演示环境已经恢复原状，报告里的数据是另外 10 次受控实验跑出来的，不拿现场这几分钟当结论。

---

## 6. 现场容易翻车的四件事

| 坑 | 现象 | 处理 |
|---|---|---|
| 90 秒不轮询 | 负载自动停、策略回默认 | 演示时保持标签页在前台；真发生了就重新点「自动 Agent」 |
| 急着下结论 | 刚开 Agent 没变化就说"没效果" | 收敛要 12–23 秒，先解释再看表 |
| 点到「四策略对照」 | 面板出现"未通过目标，安全回退" | **不要点**。那是早期的四配置比较功能（带 p99 目标），和现在这套按相对权重选参的机制不是一回事 |
| 现场数字与报告不一致 | 页面 p99 是 3.9，报告写 3.655 | 正常。现场是实时单窗探测、另一节会话；说"趋势一致"即可，别硬对数字 |

## 8. 演示顺序的建议（如果只有 5 分钟）

砍掉演示二和演示三，保留：

1. 默认 → 开 Agent → 展示它选的 300µs 与内核回读（2 分钟）
2. eBPF 洪泛 → 自动隔离 → 探测失败 → 自动恢复（2 分钟）
3. 收尾恢复默认（30 秒）
