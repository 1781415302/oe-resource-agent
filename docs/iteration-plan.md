# 赛题迭代与证据记录

当前目标：在 openEuler 24.03 LTS-SP4 上实现可部署、可观测、可回退的自适应资源管控 Agent，以真实实验决定是否保留策略。

## 验收映射

| 赛题要求 | 实现与验收 |
|---|---|
| Agent 框架 | Python 控制平面、标准 JSON 工具协议、可执行 Skills、插件注册与能力报告 |
| 感知 workload | procfs 进程与线程 CPU、上下文切换、调度等待、CPU 亲和性、显式业务目标；数据缺失单独记录 |
| sched_ext 调度 | 已验证的 SCX 生命周期与 BPF map 在线参数更新；保留默认调度作为回退 |
| 集成 scx 与性能优化 | 同期默认、原始 scx_simple、固定时间片和自适应候选对照；记录版本与真实 ops |
| eBPF hook 扩展 | 调度观测接口和资源插件；独立 hook 能力、权限、生命周期与证据模型 |
| 可复现性能数据 | 冻结配置、原始日志、重复实验、延迟与吞吐及后台代价、环境与源码/二进制哈希 |
| 演示 | 一条启动命令，清楚显示当前负载、决策原因、实际参数、效果和回退 |

## 迭代约束

1. 探索实验与最终独立评价分开，不挑选单轮最佳数字。
2. 在同一个候选二进制上比较参数；代码改变时另记版本和改动。
3. 默认调度器允许成为最佳方案；性能收益必须同时说明延迟、吞吐、后台进度和控制开销。
4. 参数在线更新优先于频繁卸载重载；更新有版本号、参数边界和实际回读。
5. 决策缺少观测、出现错误或监督失联时恢复已知状态，不把未执行动作记为成功。
6. 虚拟机实验结论适用于当前宿主和来宾配置；另行记录物理机、ARM 与多 NUMA 的验证范围。

## 当前性能基准边界

当前固定32连接的 wrk 是闭环负载，网页服务与后台共享CPU0，客户端CPU1，控制器CPU2。它能测当前混合竞争下的吞吐、请求延迟与后台进度；不能代替固定到达率 SLO、多核迁移或物理拓扑评价。后续增加固定到达率、阶段切换和调度等待观测，同时保留现有基准用于回归。

sched_ext ABI 不承诺跨内核稳定，因此当前构建锁定本机源码、兼容头和 BTF。参考：[Linux sched_ext 文档](https://www.kernel.org/doc/html/latest/scheduler/sched-ext.html)。
